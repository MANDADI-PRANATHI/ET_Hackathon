How it works — it's a pipeline, not an API wrapper

Most tools "chat over your PDFs". Sutradhar connects knowledge into a graph and lets deterministic code make the decisions a language model shouldn't.
1

Ingest mostly code

Read every document type. Tables are read by code, tags/dates/reg-refs by regex, and only prose by AI — every fact stamped with its source and a confidence.

2

Connect knowledge graph

Facts merge into one asset-centric graph — every pump, valve and vessel becomes a hub with its history, documents and rules linked to it. Not a pile of text.

3

Retrieve keyword search

A question walks the graph (the asset + its neighbours) and a keyword search over document passages. No extra model to download, nothing that needs an internet connection — this is what lets a maintenance question be answered by a safety document, with zero API calls.

4

Decide code decides

The agents let plain code make the verdict — "239 days > 182 → GAP", a rising trend, a recurring pattern. The model never guesses pass/fail, so an auditor can trust it.

5

Answer AI narrates (optional)

Cited, confidence-scored, role-aware. If a cloud/local LLM is configured it writes the final paragraph; if not, the same evidence is composed into a readable brief by local code — either way the facts, citations, and confidence are identical.

🧠 The LLM is a narrator, not the brain. Retrieval, the knowledge graph, every agent verdict, and the answer's confidence score run on plain code — a cloud API is never required to get a correct, cited answer. This matters for real plants: many can't legally send drawings or incident data to a foreign cloud. Sutradhar runs end-to-end on plant hardware with zero ongoing API dependency.
